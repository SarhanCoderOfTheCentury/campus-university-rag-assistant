# Retrieval speed and actual product demo

The optimized agent is deployed on the existing AWS endpoint and connected to the same Vercel frontend. The 61-second [demo.mp4](../demo.mp4) in the repository root uses actual browser captures of real agent requests, responses, activity and source evidence. Its captions, framing and quiet soundtrack are edited; product answers and UI states are not fabricated. Selected idle pauses are trimmed. It is a product walkthrough, not a timing benchmark.

## Measured HTTPS requests

These are small before/after samples, including transport/startup overhead, not a latency guarantee. Provider load, network conditions and Lambda cold starts vary. Full data is in [performance-validation.json](performance-validation.json).

| --- | ---: | ---: | ---: | ---: |
| Attendance, laboratory exception and medical deadline | 14.88 s | 0.21 s | 51.77 s | 24.41 s |

The final server-reported processing times were 15.41 s and 6.30 s respectively. The separate browser recording completed its programme response in 7.0 s and a current/previous attendance comparison in 15.1 s, measured by the UI's real server elapsed time. These figures exclude connection/startup work before the SSE `started` event.

## Changes

- Clear standalone university questions route locally; preferences, corrections, ambiguous requests and pronoun-based follow-ups retain the contextual LangChain planner. Scoped programme questions do not force an all-programme answer.
- Catalogues and policy scopes select complete sections directly from versioned corpus metadata. Focused questions retain vector/BM25 fusion. The separate generative reranker has been removed for this 45-section corpus. Required policy-version and conflicting-library-fine passages remain included.
- A bounded 15-minute process-local cache reuses query embeddings for the same dataset/model/dimensions and hashed query. It never caches generated answers or shares conversation transcripts.
- Generation and whole-answer verification remain separate real model operations, with one bounded repair. Source-ID, programme coverage, requested-table and semantic-support checks remain enabled. The model payload omits redundant transport metadata.
- Gemini 3.1 Flash-Lite is the primary route, with 3.5 Flash-Lite as fallback. Both use the officially supported minimal thinking level. SDK retries are disabled to avoid hidden exponential waits; each route has a 30-second per-call timeout. Output capacity remains 7,000 tokens, so speed is not obtained by cutting answers short.
- Cancellation checks coalesce for 0.75 seconds instead of issuing DynamoDB reads for every UI event. Explicit cancellation and newer-turn ownership reads run concurrently. A fresh check before memory commit preserves interrupted-request behavior.
- Lambda now has 1,792 MB, giving more CPU than the previous 1,024 MB configuration. The on-demand invocation model and existing request budgets remain; no scheduled warming service was added.
- The frontend preloads its activity/Markdown renderer while the student reads the welcome screen, avoiding a first-submit chunk fetch before progress can render.

## Verification and reproduction

36 Python tests and 60 frontend tests passed, along with the Node 22 production build. Real responses retained all nine programme rows, correct fees and duration, actual citations, and the 75%/80% regular-attendance distinction with the unchanged 85% laboratory rule and 5/3-working-day medical deadlines.

The local live-model suite passed catalogue, attendance and comparison cases, then encountered provider/network errors for four later cases. A first request immediately after a model-route deployment returned HTTP 503; the next measured run and browser requests completed successfully. These failures are not counted as passing checks. Whole-answer source validation stays enabled on every generated answer.

```bash
python -m backend.deploy.benchmark --label my-check
python -m pytest -q
npm test
npm run build
```

The benchmark consumes real provider/API quota. It measures actual SSE receipt times and stores ignored local reports under `.deploy/`.

To reproduce the film from the preserved actual capture frames, install Pillow/NumPy and FFmpeg, run from the repository root:

```bash
python scripts/render_demo.py docs/demo-scenes.json --output demo.mp4
```

The output is 1920 × 1080 H.264/AAC with web fast-start metadata. The soundtrack is generated by the renderer from original synthesized chords; there are no third-party music assets. UI attribution remains visible in the captured interface.
